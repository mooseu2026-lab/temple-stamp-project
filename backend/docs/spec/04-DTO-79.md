# temple-stamp-project — 기획 명세 ④ DTO 79개 (목록 · 배치 · 역할)

> 노션 원문을 md로 옮긴 것. 배치 규칙: 모든 DTO는 `src/main/java/com/templestamp/{패키지}` 아래, 폴더명은 확정 트리와 동일. 종류: 요청(Request)·응답(Response)·행(Row, 클래스+Lombok — Mapper 전용)·결과(Result, Service 간)·enum·래퍼. `Row`만 클래스, 나머지는 `record`.

## 1. global/response — 공통 래퍼 (3)
| DTO | 역할 |
|---|---|
| ApiResponse<T> | 모든 응답을 성공여부·본문·에러·시각 한 껍질로 통일. Controller 반환과 GlobalExceptionHandler가 함께 사용 |
| PageResponse<T> | 페이징 목록 + 페이지·크기·전체개수·다음페이지 여부. 생각상자·보상·인쇄신청 목록 |
| ItemsResponse<T> | 페이징 없는 소규모 목록을 객체로 감쌈. 권역·구절·인증서 목록 |

## 2. global/error (1)
| ErrorResponse | 에러 코드·안내 문구·필드별 검증 결과. ApiResponse의 error 자리 전용. ErrorCode·BusinessException·GlobalExceptionHandler와 같은 패키지 |

## 3. global/type — enum (6)
| enum | 역할 |
|---|---|
| Tier | AGE20~60·RIDER·FOREIGN. 확장문구·미션 풀 결정. NULL→AGE30 |
| AccuracyGrade | HIGH/MID/LOW. LOW는 서버가 거부 |
| StampStatus | GPS_DONE·QR_DONE·COMPLETED·EXPIRED·PENDING·REJECTED. Service 내부 비교 전용 |
| VerifyMethod | GPS_QR / EVIDENCE |
| UploadPurpose | PHOTO/EVIDENCE — 저장소 키 접두어 |
| AgreementType | LOCATION_SERVICE / EBOOK_PUBLIC. DB CHECK와 값 일치 |
요청은 enum으로 받아 잘못된 값을 Jackson이 400으로, 응답은 String.

## 4. auth/dto (3)
| SignupRequest | 이메일 100자·비밀번호 8~50자 영문+숫자+특수·닉네임 2~20자. 중복 확인은 Service |

## DTO 없는 패키지
- photo — MissionSubmitRequest.photoKey로 들어오고 Passport·SitePage 응답에 photoKey로 실림
- content — 정적 json(guide·i18n) 서빙

## 계층 규칙
Request → Controller `@Valid` / Response → Service 조립 후 `ApiResponse.ok()` / Row → Mapper XML resultType(Controller 밖 금지) / CompletionResult → Service 간 전용.

## [가정] — admin 신규분
PendingStampRow.createdAt 컬럼명 · QR 토큰 만료(expiresAt null 허용) · 좌표 한국 영역(위도 33~39, 경도 124~132) · 반경 30~1000m · 사찰명 100·설명 1000·QR 안내 200·라이더 정보 300·코스명 100 · 확장문구 500·미션 300 · version_no/variant_no는 Service 채번 · 전자책 조판은 외부·배치.
