## 1. 점검 원칙

1. **"있다"가 아니라 "돈다"** — 기능은 newman 요청이 실제로 200/4xx를 받고 SQL 채점이 맞아야 ✅. 코드만 있으면 ⚠(미검증), 없으면 —.
2. **도구부터 검증** — 점검 도구가 결함을 못 잡으면 결과가 무의미하다(챕터 7에서 cleanup·mapper-check·H12 셋이 조용히 거짓 통과). §6 자가검증을 **먼저** 돈다.
3. **2회 동일** — run-all.sh 2회 결과(요청 수·단언 수·SQL 채점)가 완전히 같아야 멱등. 다르면 cleanup 누락이나 시퀀스 의존.
4. **정본 대조** — 엔드포인트는 `endpoint-scan.js` 결과 = `docs/audit/endpoints.md`(76개 예상). 기능은 §2 표. 둘 다 이 점검에서 갱신한다.
5. 코드·스키마를 고치지 않는다. 결함은 **보고**하고 ⚠/❌로 남긴다. 예외: 점검 도구 결함은 즉시 고치고 재실행.

## 3. 엔드포인트 (endpoint-scan.js가 정본)

`node endpoint-scan.js`를 돌려 컨트롤러에서 **실제** 목록을 뽑고 `docs/audit/endpoints.md`를 덮어쓴다. 예상 76개(73 + 재집계 2 + 회수 1). 각 행에 열 4개: `메서드 경로 | 인증(없음/USER/ADMIN) | newman 요청 id | 판정`.

판정 규칙: newman 요청이 1개 이상 있고 통과 → ✅ / 코드는 있는데 newman 없음 → ⚠(챕터 8·9는 "미검증(ch8/9)") / 스캔에 없는데 문서에 있음 → ❌(문서 오류).

집계 줄: `엔드포인트 N · ✅ a · ⚠ b(그중 ch8/9 c) · ❌ d`. b − c가 0이어야 챕터 8 진입.

비로그인 허용 목록을 별도 표로: `GET /api/certificates/verify/*`·회원가입·로그인·refresh·권역/코스/사찰 조회 등 — `SecurityConfig`에서 뽑은 것과 실측(토큰 없이 200)이 일치해야 한다.
