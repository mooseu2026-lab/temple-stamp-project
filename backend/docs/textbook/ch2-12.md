## 1. 이 챕터가 완성하는 사용자 흐름 ↔ 프로그램 흐름

```
[사용자]  홈 → 여권 화면(S-03)          → 권역 상세(S-04)            → 싱글페이지(S-05)           → 가는 법(S-17)
             │                                │                            │                           │
[요청]    GET /api/regions              GET /api/courses?regionId=    GET /api/sites/{id}/page     GET /api/sites/{id}/guide
             │                          GET /api/courses/{id}         GET /api/sites/{id}          GET /api/verses/{n}
             ▼                                ▼                            ▼                           ▼
[필터]    RequestIdFilter → CachedBody → CoordinateGuard → JwtAuthenticationFilter(토큰 있으면 금고에 기록, 없으면 통과)
             ▼
[Security] permitAll (공개·선택 등급) — 비로그인도 200
             ▼
[Controller] @AuthenticationPrincipal 로 user 수령 (비로그인이면 null) → locale 결정 → Service 호출
             ▼
[Service]  @Transactional(readOnly=true) 조회 / 로그인 시 phrase_seen·task_seen INSERT IGNORE
             ▼
[응답]     ApiResponse{ success, data, error:null, timestamp(+09:00) } + 헤더 X-Request-Id
```

**이 챕터의 핵심 한 줄**: 컨트롤러는 ① 입력 검증(@Validated·@Positive) ② 로그인 여부 판별(null 허용) ③ locale 결정, 이 셋만 하고 판단은 전부 Service에 넘긴다.

## 2. ⚠️ 먼저 고칠 것 — `@AuthenticationPrincipal(required = false)` 는 존재하지 않는 속성

지난 회차 문서와 인수인계 §8에 `@AuthenticationPrincipal(required = false)`가 여러 번 나온다. **컴파일되지 않는다.**
Spring Security 공식 API 기준 이 어노테이션의 속성은 `errorOnInvalidType`(기본 false)과 `expression` 둘뿐이다.

비로그인을 허용하는 올바른 쓰기는 **아무 속성 없이** `@AuthenticationPrincipal AuthenticatedUser user` 다.
- 토큰이 있으면 필터가 `AuthenticatedUser`를 principal로 넣었으므로 그대로 주입된다.
- 토큰이 없으면 principal은 스프링의 `"anonymousUser"`(String) 이고, `AuthenticatedUser` 타입에 맞지 않으므로 `errorOnInvalidType=false` 규칙에 따라 **null 이 주입**된다.

즉 "선택" 등급의 null 처리는 `required` 가 아니라 **타입 불일치 → null** 로 이미 구현되어 있다. 이 문서의 코드는 전부 이 방식이다.
저장소에 `required = false`가 남아 있으면 Claude Code STEP 1에서 전수 제거한다.

## [기본 29] RegionController — 권역 9개 목록

**파일** `backend/src/main/java/com/templestamp/course/RegionController.java`

```java
// backend/src/main/java/com/templestamp/course/RegionController.java
package com.templestamp.course;

import com.templestamp.course.dto.RegionResponse;
import com.templestamp.global.response.ApiResponse;      // 모든 응답의 겉포장. 규약 §1
import com.templestamp.global.response.ItemsResponse;    // 페이징 없는 소규모 목록 포장. 배열을 맨 바깥에 두지 않는다
import lombok.RequiredArgsConstructor;                   // final 필드 생성자를 롬복이 만들어 준다 → 생성자 주입
import lombok.extern.slf4j.Slf4j;                        // log.debug(...) 를 쓰기 위한 로거 자동 생성
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RestController;

/**
 * F-04 권역 조회. 9권역 + 각 권역의 코스 수를 한 번에 준다.
 * 인가 등급: 공개 — SecurityConfig 의 [course] 구역에서 GET /api/regions permitAll.
 * 로그인 정보가 필요 없으므로 @AuthenticationPrincipal 을 받지 않는다.
 */
@RestController                                          // @Controller + @ResponseBody. 반환값이 곧 JSON 본문
@RequestMapping("/api/regions")                          // 이 클래스의 모든 메서드 앞에 붙는 공통 경로
@RequiredArgsConstructor                                 // final 필드 1개짜리 생성자 → 스프링이 CourseService 를 꽂아 준다
@Slf4j
public class RegionController {

    private final CourseService courseService;           // 권역도 코스 도메인의 일부라 CourseService 가 맡는다 (별도 RegionService 없음)

    /** GET /api/regions → { items:[ {regionId, name, courseCount}, ... ] } */
    @GetMapping                                          // 경로 추가 없음 = /api/regions 그대로
    public ApiResponse<ItemsResponse<RegionResponse>> list() {
        log.debug("GET /api/regions");                   // 파라미터가 없어서 적을 것도 없다. 흐름 추적용
        return ApiResponse.ok(ItemsResponse.of(courseService.getRegions()));
        // 안쪽부터: Service 가 List<RegionResponse> → ItemsResponse 로 감쌈 → ApiResponse 로 또 감쌈
        // 결과 JSON: { "success":true, "data":{ "items":[...] }, "error":null, "timestamp":"..." }
    }
}
```

**왜 이렇게 하는가**
- 권역은 9개로 고정이고 페이징이 필요 없다 → `ItemsResponse`. 나중에 `totalCount` 같은 필드가 붙어도 프론트가 안 깨지도록 배열을 객체로 감싼다.
- Region 전용 Service를 만들지 않는다. 클래스 수를 늘리는 것보다 "권역·코스·자리는 한 묶음"이라는 도메인 경계를 지키는 것이 중요하다.

**자주 만나는 오류**
- `courseService.getRegions()` 가 없다 → Service 계약표(§3) 확인. 이름이 `findRegions` 등이면 컨트롤러를 맞춘다.
- 응답이 `[...]` 배열로 나온다 → `ItemsResponse.of` 를 빼먹은 것.

**확인포인트** `curl -s http://localhost:8080/api/regions | jq '.data.items | length'` → `9`

## [기본 30] CourseController — 코스 목록·상세 (선택 인증)

**파일** `backend/src/main/java/com/templestamp/course/CourseController.java`

```java
// backend/src/main/java/com/templestamp/course/CourseController.java
package com.templestamp.course;

import com.templestamp.course.dto.CourseDetailResponse;
import com.templestamp.course.dto.CourseResponse;
import com.templestamp.global.response.ApiResponse;
import com.templestamp.global.response.ItemsResponse;
import com.templestamp.global.security.AuthenticatedUser;   // 필터가 금고에 넣어 둔 로그인 사용자. 비로그인이면 null
import com.templestamp.global.web.LocaleUtil;                // Accept-Language → ko/en/ja/zh, 없거나 미지원이면 ko
import jakarta.validation.constraints.Positive;              // 0·음수 차단. 경로변수·쿼리 검증
import lombok.RequiredArgsConstructor;
import lombok.extern.slf4j.Slf4j;
import org.springframework.security.core.annotation.AuthenticationPrincipal;
import org.springframework.validation.annotation.Validated;  // ★ 메서드 파라미터의 @Positive 를 살리는 스위치. 없으면 검증이 조용히 안 돈다
import org.springframework.web.bind.annotation.*;

/**
 * F-04 코스 목록·상세. 인가 등급 "선택" — 토큰 있으면 progress 결합, 없으면 progress:null.
 * SecurityConfig [course] 구역: GET /api/courses/** permitAll.
 */
@RestController
@RequestMapping("/api/courses")
@RequiredArgsConstructor
@Validated                                                   // 클래스에 붙여야 @PathVariable/@RequestParam 의 제약이 검사된다
@Slf4j
public class CourseController {

    private final CourseService courseService;

    /**
     * GET /api/courses?regionId=3
     * regionId 는 선택 — 없으면 전체 코스. 0 이하면 400 COMMON-4000 (ConstraintViolationException → GlobalExceptionHandler)
     */
    @GetMapping
    public ApiResponse<ItemsResponse<CourseResponse>> list(
            @RequestParam(required = false) @Positive Long regionId,   // required=false 는 @RequestParam 의 속성이다(있음). null 이면 @Positive 는 검사 안 함
            @AuthenticationPrincipal AuthenticatedUser user) {          // ★ 속성 없음. 비로그인 → "anonymousUser"(String) 이라 타입 불일치 → null 주입
        Long userId = user == null ? null : user.userId();              // Service 는 Long 만 받는다. null = 비로그인 = progress 안 붙임
        log.debug("GET /api/courses regionId={} userId={}", regionId, userId);
        return ApiResponse.ok(ItemsResponse.of(courseService.getCourses(regionId, userId)));
    }

    /**
     * GET /api/courses/{courseId}  + 헤더 Accept-Language
     * 사찰 5곳의 좌표·반경을 한 번에 내려준다 — 이 뒤로 거리 계산은 단말이 한다(원칙①). 좌표는 서버로 되돌아오지 않는다.
     */
    @GetMapping("/{courseId}")
    public ApiResponse<CourseDetailResponse> detail(
            @PathVariable @Positive Long courseId,
            @RequestHeader(value = "Accept-Language", required = false) String acceptLanguage,   // 헤더는 없을 수 있다 → required=false
            @AuthenticationPrincipal AuthenticatedUser user) {
        String locale = LocaleUtil.resolve(acceptLanguage);           // "en-US,en;q=0.9" → "en". null → "ko"
        Long userId = user == null ? null : user.userId();
        log.debug("GET /api/courses/{} locale={} userId={}", courseId, locale, userId);
        return ApiResponse.ok(courseService.getCourseDetail(courseId, userId, locale));
        // 코스가 없거나 status≠ACTIVE 이면 Service 가 BusinessException(COURSE_4041) → 404 JSON
    }
}
```

**왜 이렇게 하는가**
- `@Validated`를 **클래스**에 붙이는 이유: `@RequestBody @Valid`는 스프링 MVC가 검사하지만, 경로변수·쿼리의 `@Positive`는 메서드 검증 프록시가 필요하고 그 프록시는 클래스 레벨 `@Validated`로 켜진다. 빠뜨리면 `regionId=0`이 그대로 Service까지 간다.
- 로그인 판별을 컨트롤러가 `null`로 넘기는 이유: Service가 `AuthenticatedUser`를 알면 시큐리티에 의존하게 된다. Service는 `Long userId`만 안다 → 테스트가 쉽다.

**자주 만나는 오류**
- `GET /api/courses?regionId=0` 이 200으로 나온다 → 클래스에 `@Validated` 없음, 또는 `GlobalExceptionHandler`에 `ConstraintViolationException` 핸들러(인수인계 §5-10) 없음.
- 비로그인 요청이 500 `ClassCastException` → 어딘가에 `@AuthenticationPrincipal(errorOnInvalidType = true)` 가 있다. 기본값(false)으로 둔다.

**확인포인트** 확인포인트 9종 중 ①·③·④ (다음 카드 14에서 삼중검증)

## [기본 31] SiteController — 사찰 기본·싱글페이지·가는 법

**파일** `backend/src/main/java/com/templestamp/site/SiteController.java`

```java
// backend/src/main/java/com/templestamp/site/SiteController.java
package com.templestamp.site;

import com.templestamp.global.response.ApiResponse;
import com.templestamp.global.security.AuthenticatedUser;
import com.templestamp.global.type.Tier;                    // 확장문구 target. 문자열이 enum 밖이면 Jackson/Converter 가 400
import com.templestamp.global.web.LocaleUtil;
import com.templestamp.site.dto.SiteGuideResponse;
import com.templestamp.site.dto.SitePageResponse;
import com.templestamp.site.dto.SiteResponse;
import jakarta.validation.constraints.Positive;
import lombok.RequiredArgsConstructor;
import lombok.extern.slf4j.Slf4j;
import org.springframework.security.core.annotation.AuthenticationPrincipal;
import org.springframework.validation.annotation.Validated;
import org.springframework.web.bind.annotation.*;

/**
 * F-05·06·07 싱글페이지, F-21 사찰 가는 법, 사찰 기본 정보.
 * 인가 등급: /{id}·/guide 공개, /page 선택(로그인 시 verifyState + seen 기록).
 * SecurityConfig [site] 구역: GET /api/sites/** permitAll.
 *
 * locale 우선순위(인수인계 §4): 쿼리 locale → Accept-Language → users.locale → ko
 *   컨트롤러는 앞의 둘만 합쳐 "힌트" 하나로 만들고, users.locale·ko 폴백은 Service(로그인 여부를 아는 곳)가 한다.
 */
@RestController
@RequestMapping("/api/sites")
@RequiredArgsConstructor
@Validated
@Slf4j
public class SiteController {

    private final SiteService siteService;                   // 사찰 기본 정보 1건
    private final SitePageService sitePageService;           // 8블록 조립 전담 — 확장문구·미션 선택 규칙이 여기 있다
    private final SiteGuideService siteGuideService;         // 참배 순서 7자리 조립 (R1: LEFT JOIN 조건은 ON 에)

    /** GET /api/sites/{siteId} — 좌표·반경·QR 힌트. 없거나 비활성이면 404 SITE-4040 */
    @GetMapping("/{siteId}")
    public ApiResponse<SiteResponse> site(
            @PathVariable @Positive Long siteId,
            @RequestHeader(value = "Accept-Language", required = false) String acceptLanguage) {
        String locale = LocaleUtil.resolve(acceptLanguage);
        log.debug("GET /api/sites/{} locale={}", siteId, locale);
        return ApiResponse.ok(siteService.getSite(siteId, locale));
    }

    /**
     * GET /api/sites/{siteId}/page?target=RIDER&locale=en
     * courseId 를 받지 않는다 — uk_course_site_site(site_id) 덕분에 siteId 만으로 코스·자리·구절이 결정된다(인수인계 §4).
     * target 없으면 Service 가 users.tier(UserMapper.findTier) → AGE30 순으로 정한다. 후보 0건이면 AGE30 폴백 → 그래도 0건 SITE-5001.
     * 매번 새 문구·미션이 나가야 하므로 캐시 금지(명세 §10, S-05).
     */
    @GetMapping("/{siteId}/page")
    public ApiResponse<SitePageResponse> page(
            @PathVariable @Positive Long siteId,
            @RequestParam(required = false) Tier target,                  // "RIDER" → Tier.RIDER. 이상한 값(AGE99)은 400 COMMON-4003 (타입 변환 실패 = MethodArgumentTypeMismatchException. 4000 은 @Validated 검증 실패)
            @RequestParam(required = false) String locale,                // 쿼리 locale (1순위)
            @RequestHeader(value = "Accept-Language", required = false) String acceptLanguage,   // 2순위
            @AuthenticationPrincipal AuthenticatedUser user) {            // 비로그인 null → verifyState:null, seen 기록 안 함
        String localeHint = locale != null ? locale : acceptLanguage;     // 둘 다 null 이면 null 로 넘겨 Service 가 users.locale → ko 결정
        log.debug("GET /api/sites/{}/page target={} localeHint={} userId={}",
                siteId, target, localeHint, user == null ? null : user.userId());
        return ApiResponse.ok(sitePageService.getPage(siteId, target, localeHint, user));
        // Service 안에서: SiteRow → VerseBlock → PhraseBlock(seen 우선) → MissionBlock → Viewpoint·Badge → RiderInfo → VerifyState
    }

    /**
     * GET /api/sites/{siteId}/guide — 사찰 가는 법 7자리.
     * ★ Accept-Language 를 받지 않는다(의견02 §4): 사전(shrine_element)이 한국어 한 벌뿐이라 반쪽 번역을 내보내지 않는다.
     *   형제 API 와 규칙이 다르므로 프론트 전달 필수. 번역 원고가 오면 shrine_element_i18n + COALESCE 한 줄로 붙는다.
     */
    @GetMapping("/{siteId}/guide")
    public ApiResponse<SiteGuideResponse> guide(@PathVariable @Positive Long siteId) {
        log.debug("GET /api/sites/{}/guide", siteId);
        return ApiResponse.ok(siteGuideService.getGuide(siteId));
        // 항상 steps 7칸. 없는 자리는 present=false + 대체 서술(passage). 연속 공백 반복 문제는 의견02 §1 결정 대기
    }
}
```

**왜 이렇게 하는가**
- `target`을 `String`이 아니라 `Tier`로 받는다: 잘못된 값은 컨트롤러 진입 전에 400으로 끊긴다. Service 안에 `valueOf` 분기가 하나도 안 생긴다. (`USER_4001`은 PATCH /users/me 전용 — 인수인계 §5-11)
- `/page`만 `user` 통째로 넘기는 이유: verifyState 조회에 userId, tier 폴백에 userId, seen 기록에 userId — 세 곳이 쓰는데다 "로그인 여부" 자체가 분기 조건이라 `null` 검사를 Service 한 곳에서 하는 게 낫다. 저장소 시그니처가 `Long userId`면 그에 맞춘다.
- 컨트롤러에 조립 코드가 한 줄도 없다. 8블록 조립·확장문구 선택·가는 법 대체 서술은 전부 Service. DTO는 record만(인수인계 §5-6).

**자주 만나는 오류**
- `?target=rider` (소문자) → 400. enum 변환은 대소문자를 구분한다. 프론트에 대문자 고정을 알린다.
- `/page` 를 두 번 호출해도 문구가 안 바뀐다 → 비로그인이거나(seen 미기록이 정상) 후보가 1편뿐(현재 시드는 tier당 1버전 — 의견03 §8. 코드 문제가 아니다).
- `/guide` 응답이 7칸 미만 → `SiteGuideMapper.xml`의 `se.site_id = #{siteId}` 가 WHERE 로 내려갔다(R1). ON 으로 되돌린다.

**확인포인트** 9종 중 ②·⑤·⑥

## [기본 32] VerseController — 오관게 5구

**파일** `backend/src/main/java/com/templestamp/verse/VerseController.java`

```java
// backend/src/main/java/com/templestamp/verse/VerseController.java
package com.templestamp.verse;

import com.templestamp.global.response.ApiResponse;
import com.templestamp.global.response.ItemsResponse;
import com.templestamp.verse.dto.VerseResponse;
import jakarta.validation.constraints.Max;
import jakarta.validation.constraints.Min;
import lombok.RequiredArgsConstructor;
import lombok.extern.slf4j.Slf4j;
import org.springframework.validation.annotation.Validated;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.PathVariable;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RestController;

/**
 * 오관게 5구 조회. 인트로 2단·싱글페이지 VerseBlock 과 같은 원문을 쓴다.
 * 인가 등급: 공개. SecurityConfig [verse] 구역: GET /api/verses/** permitAll.
 * verseNo 는 gwan_verse.verse_no TINYINT PK, CHECK (1~5) — DB 제약을 컨트롤러 검증으로 한 번 더 미러링한다.
 */
@RestController
@RequestMapping("/api/verses")
@RequiredArgsConstructor
@Validated
@Slf4j
public class VerseController {

    private final PhraseService phraseService;              // 구절·확장문구·미션은 한 서비스(verse 도메인). 별도 VerseService 없음

    /** GET /api/verses → 5건, verse_no 순 */
    @GetMapping
    public ApiResponse<ItemsResponse<VerseResponse>> list() {
        log.debug("GET /api/verses");
        return ApiResponse.ok(ItemsResponse.of(phraseService.getVerses()));
    }

    /** GET /api/verses/{verseNo} — 6 이상·0 이하는 400 COMMON-4000 (DB 까지 안 간다). 1~5 인데 없으면 404 VERSE-4040 */
    @GetMapping("/{verseNo}")
    public ApiResponse<VerseResponse> one(
            @PathVariable @Min(1) @Max(5) Integer verseNo) {   // @Positive 대신 상한까지 — 99 를 DB 에 물어보는 낭비를 막는다
        log.debug("GET /api/verses/{}", verseNo);
        return ApiResponse.ok(phraseService.getVerse(verseNo));
    }
}
```

**왜 이렇게 하는가** `GET /api/verses/99` 는 확인포인트 ⑥에서 **400**이어야 한다(404가 아님). 값 자체가 정의역 밖이라 "없다"가 아니라 "잘못된 요청"이다. `@Min/@Max`가 그 판정을 DB 앞에서 끝낸다.

**자주 만나는 오류** `/api/verses/99` 가 404로 나온다 → `@Validated` 누락. 500이 나온다 → `ConstraintViolationException` 핸들러 누락(인수인계 §5-10).

## [기본 33] SecurityConfig 구역 append + ErrorCode append

### SecurityConfig — `[course] [site] [verse]` 구역 줄만 추가 (기존 줄 수정 금지, Git 규칙 §12)

```java
// backend/src/main/java/com/templestamp/global/config/SecurityConfig.java — authorizeHttpRequests 안, 기존 permitAll 줄 아래에 append
```
