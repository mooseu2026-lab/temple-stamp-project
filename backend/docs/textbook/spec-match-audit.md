# 감사 H — 기획 명세 ↔ 구현 매칭 (정본 · 노션용)

작성 2026-09-07 · 대상: 기획 명세(목적·기능 F-01~F-23·API·DB 28표·규칙·에러코드·권한 매트릭스) vs 현재 구현(챕터 0~9, API 91, 표 36) · 목적: **영역별 매칭율을 숫자로 재고, 100% 미만인 것을 "재구현 / 의도적 변경(사유) / 미결"로 가른다.** 재구현 여부는 감사 결과를 보고 예성이 결정한다.

---

## 1. 판정 기준

| 판정 | 뜻 | 매칭율 계산 |
|---|---|---|
| ✅ 일치 | 명세 항목이 그대로 구현됨 | 100 |
| ⬆ 초과 | 명세보다 강하거나 넓게 구현됨(상위 호환) | 100 이상으로 세되 **프론트가 알아야 할 차이**를 적는다 |
| 🔁 의도적 변경 | 챕터 진행 중 예성 결정으로 명세와 다르게 만든 것 | 100으로 세되 **결정 출처(챕터·날짜)** 필수. 출처가 없으면 ⛔ |
| ⛔ 미달 | 명세에 있는데 없거나 다르게 됐고 결정 기록이 없음 | 0 — 재구현 후보 |
| ❓ 미결 | 명세 자체가 미결(Q1~Q8) 또는 명세 안에서 서로 모순 | 분모에서 제외, 결정 필요 목록으로 |

영역 매칭율 = (✅ + ⬆ + 🔁) / (❓ 제외 항목 수). **재구현 판단은 ⛔에 대해서만** 한다.
