## 2. 되돌림 4건

### 2-1 refresh 토큰 14일 (H-1)
- `app.jwt.refresh-days` 기본값 7 → **14**. 쿠키 `Max-Age`·`refresh_token.expires_at` 계산이 같은 값을 쓰는지 확인(하드코딩 7 금지).
- 청소기 유예(만료+24h)·재사용 탐지 규칙 불변. 기존 발급분은 그대로 만료(마이그레이션 없음).
- 인수인계 §4-1·정리.md §4 갱신.

### 2-2 행동과제 50/30/20 가중 (H-2)
- `mission` 표에 **출처 축** 추가: `scope ENUM('SITE','VERSE','COMMON') NOT NULL DEFAULT 'VERSE'`, `site_id BIGINT NULL`(scope=SITE일 때만, FK site). 유니크 `(verse_no, tier, variant_no)`는 유지하되 SITE 과제는 `(site_id, tier, variant_no)`로 별도 유니크 — 생성 컬럼 `site_key = IFNULL(site_id,0)`(챕터 8 규칙 재사용). ALTER ⑲.
- 선택 규칙(`PhraseService.pickMission`):
  1. 후보 = tier(없으면 AGE30) 안에서 SITE(이 사찰) / VERSE(이 구절) / COMMON 세 풀, 각각 같은 코스 `task_seen` 제외
  2. 세 풀 중 비어 있지 않은 풀에 **50 / 30 / 20 가중**으로 하나를 고르고, 그 풀에서 미노출 우선 RAND
  3. 세 풀 다 비면 기존 대체안(챕터 5 결정: 미션 없이 도장을 끝낼 수 없으므로) 유지 + WARN 로그 1줄 `TASK-POOL-EMPTY site={id}`
  4. 명세의 "사진 과제인데 사진 있음" 제외는 **하지 않는다**(사진은 선택 항목이라 과제 유형 축이 없음 — 결정 기록)
- 시더: 기존 36편은 `VERSE`로. COMMON 5편 추가(구절 무관). SITE 과제는 콘텐츠 트랙(CSV 반입 양식에 `scope`·`site_name` 열 추가 — 챕터 8 CSV 반입기가 mission도 받는지 확인, 아니면 관리자 등록 API `POST /api/admin/contents/missions`에 scope 필드만 추가, 신설 아님).
- 관리자 목록 응답에 `scope`·`siteName` 필드.

### 2-3 확장문구 권역 내 version 중복 금지 (H-3)
- 규칙: 같은 코스(순례) 안에서 이미 본 `version_no`는 **다른 구절에서도** 제외. `phrase_seen`은 이미 (user, course, phrase) 단위이므로 조회 시 `version_no NOT IN (이 코스에서 본 version_no들)` 조건 추가.
- 완화 순서: ① 미노출 + version 미중복 → ② 미노출(version 중복 허용) → ③ 가장 오래전 것(LRU, 기존). 각 단계 적용 여부를 응답에 싣지 않는다(내부).
- 5구 × 5버전이므로 코스 5자리를 다 돌면 version 5개를 각각 다르게 볼 수 있다 — JUnit이 "한 코스 5자리에서 version_no 전부 상이"를 실측.

### 2-4 전자책 `has_other_face` 제외 (H-5)
- 전자책 재료 수집(`EbookService.materialsOf`)에서 사진 조건 `is_private = 0 AND has_other_face = 0`. 제외된 자리는 "사진 없음"(실패 아님, 챕터 9 규칙).
- 스냅샷 해시 재료에서도 제외(플래그를 바꾸면 해시가 달라져 새 책이 나오는 것이 맞다).
- 인쇄주문·인증서 무관.
