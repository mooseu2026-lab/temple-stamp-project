# 개발용 기능 콘솔(dev-console) — 정본

작성 2026-09-07 · 목적: `localhost:8080`에서 **지금까지 만든 기능 58개를 눈으로 보고 눌러 볼 수 있는** 최소한의 화면. 정식 프론트가 아니다 — 프론트가 붙는 날 **통째로 삭제**한다. 그래서 설계의 첫 원칙은 "예쁨"이 아니라 **"지우기 쉬움"** 이다.

---

## 1. 삭제 가능 설계 (가장 중요)

| 원칙 | 규칙 |
|---|---|
| 새 API 0개 | 콘솔은 기존 엔드포인트 91개만 호출한다. 컨트롤러·서비스·매퍼·표에 **한 줄도** 추가하지 않는다. endpoint-scan은 여전히 91 |
| 한 폴더 | 모든 파일은 `src/main/resources/dev-console/` 아래(**`static/`이 아니다** — Spring 기본 정적 서빙에 노출되지 않게). `index.html`·`console.css`·`console.js`·`checks.js`·`README.md` 5개 |
| 한 클래스 | `com.templestamp.devconsole.DevConsoleConfig` — `@Profile("!prod")` + `WebMvcConfigurer`로 `/console/**` → `classpath:/dev-console/` 매핑, `/` → `/console/` 리다이렉트. 이 클래스가 없으면 위 폴더는 어디서도 안 보인다 |
| 한 줄 | `SecurityConfig`의 비로그인 허용 목록에 `/console/**` 한 줄, **같은 `!prod` 조건** 아래. 주석 `// DEV-CONSOLE: 프론트 결합 시 삭제` |
| prod에서 부재 | prod 프로파일로 기동하면 `/console/**` 404·`/`는 지금처럼 401. S26으로 실측 |
| 삭제 절차 | 정리.md §9에 "프론트 결합 시 삭제 목록 3개"를 적고, `docs/verify/dev-console-remove-check.sh`(폴더·클래스·보안 줄이 남아 있으면 실패)를 둔다. 프론트 결합 점검에서 이 스크립트를 돈다 |
| 데이터 흔적 | 콘솔이 만드는 계정·데이터는 이메일 접두 `console-`로만. `cleanup.sql`에 그 접두 삭제 1줄 추가 → newman 2회 동일에 영향 없음 |
| 빌드 없음 | 순수 HTML/CSS/JS. 번들러·npm 없음. Tailwind는 CDN 한 줄(dev 전용이라 허용) |

## 2. 화면 구성 (한 페이지, 왼쪽 메뉴 + 오른쪽 작업창 + 아래 응답창)

| 메뉴 | 작업창 | 부르는 API |
|---|---|---|
| 상태 | 헬스·현재 로그인(이메일·역할)·시드 숫자(권역·코스·사찰) | `/health`·`/api/users/me`·`/api/regions`·`/api/courses` |
| 회원 | 가입(접두 `console-` 강제)·로그인·refresh·내 정보·탈퇴(확인창 2회) — 테스트 계정 3개(U1·ED1·ADM)는 dev 전용으로 버튼 한 번 로그인 | 인증·회원 10 |
| 권역·코스·사찰 | 권역 → 코스 → 자리·후보 → 사찰 상세 8블록·가는 법 7칸(present:false는 회색으로) | 조회 6 + 구절 2 |
| 순례 | 시작·여권·진행률 막대 | 순례 2 |
| 현장 인증 | 1단계 GPS(siteId만 — 좌표는 보내지 않는다는 문구 표시)·2단계 QR(dev에서는 관리자 QR 발급으로 토큰 받아 붙여넣기)·3단계 미션 원고 표시 + 다짐 제출 → 도장·확장문구 표시·by-slot | 현장 인증 6 + 관리자 QR |
| 기록 | presign → 파일 PUT → 사진 등록·문장·생각상자(isPrivate 토글)·flashback·명상 | 기록 12 |
| 완주·인증서·보상 | 완주 목록·인증서 목록·1장 조회(downloadUrl 열기)·**진위 확인**(토큰 없이 새 창)·보상 목록(claimable 배지)·수령 신청 | 4 + 인증서 1장 |
| 원고 | 편집자: 등록·수정·제출·내 목록 / 관리자: 심사 목록·승인·반려·퇴역·CSV 반입(dryRun 체크박스) | 편집자 4 + 관리자 5 |
| 전자책·인쇄 | 요청 → 상태(REQUESTED/READY 폴링 5초) → downloadUrl → 인쇄주문 → 내 주문·취소 | 전자책 3 + 인쇄 4 |
| 관리자 | 사찰 UPSERT·도장 심사·재집계·인증서 회수·보상 심사·사용자 목록(status 필터)·청소기 실행(건수 표시)·인쇄 심사 | 관리자 전부 |
| **기능 체크** | §3 | |

공통: 응답창은 **상태코드 배지 + JSON pretty**(`success/data/error/timestamp` 그대로) + 걸린 시간. 4xx는 주황, 5xx는 빨강(5xx가 보이면 그 자체가 결함). 토큰은 메모리(JS 변수)에만 — localStorage 금지. refresh는 기존 쿠키 흐름 그대로.

## 3. 기능 체크 장치 (`checks.js`)

브라우저 안의 작은 newman. F01~F58 각 행에 **[확인]** 버튼. 누르면 정해진 순서로 API를 부르고 응답을 판정해 ✅/❌를 그 행에 표시하고, 위에 집계(✅ n / ❌ m / 미실행 k)와 **[전체 실행]**.

| 규칙 | |
|---|---|
| 안전 우선 | 파괴적 기능(탈퇴·회수·퇴역·취소)은 `console-` 계정에만, 실행 전 확인창 |
| 판정 = 응답 | 상태코드·필드 존재·값으로만 판정. DB를 보지 못하므로 newman의 SQL 채점을 대신하지 못한다 — 화면 상단에 "정식 판정은 newman·JUnit(점검 F)이며 이 체크는 눈으로 보는 용도"라고 고정 문구 |
| 시간 기반 | F14(60분 만료)·F51 청소기 생성·F55는 "관리자 청소기 실행 버튼 → 건수 ≥ 1"로 대체 판정, 행에 "대체" 표시 |
| 파일 | F58 저장소 실재는 downloadUrl 응답을 `fetch`해 `%PDF` 4바이트 확인(같은 출처면 가능, 아니면 "브라우저에서 미확인" 표시) |
| 순서 의존 | 체크는 순서대로 실행되며 앞 단계의 id를 뒤가 쓴다. 중간 실패 시 뒤는 "건너뜀" |
| 결과 저장 | 마지막 실행 결과를 JSON으로 다운로드(노션 첨부용). 서버에 저장하지 않는다 |

## 4. 금지

- 새 컨트롤러·서비스·매퍼·표·설정값 추가 금지(설정값이 필요하면 콘솔 안 상수).
- `static/`·`templates/`·Thymeleaf 사용 금지(정식 프론트로 오해될 수 있는 구조는 만들지 않는다).
- 토큰 localStorage 저장 금지, 비밀번호 화면 표시 금지(테스트 계정 비번은 `console.js` 상수, dev 전용 명시).
- 콘솔 코드가 JUnit·newman 어느 것에도 참조되지 않는다(삭제 시 테스트가 깨지면 설계 실패).
