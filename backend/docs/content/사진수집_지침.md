# 사찰 대표 사진 수집 지침 (C1 STEP 6 · 2026-09-07)

사진 파일은 이 저장소에 **넣지 않는다.** 예성이 모으고 FE-2 가 내려받는다.
이 문서가 정하는 것은 **어디서 가져와도 되는가**와 **무엇을 적어 두어야 하는가** 둘뿐이다.

> **출처를 모르는 사진은 쓰지 않는다.** 절 사진은 대개 누군가 찍은 것이고, 그 사람에게 권리가 있다.
> "인터넷에 있으니 써도 된다" 는 없다. 라이선스를 확인하지 못했으면 **한지 텍스처 폴백**으로 둔다 —
> 빈 자리는 사고가 아니지만, 남의 사진은 사고다.

## 1. 써도 되는 소스 넷

| # | 소스 | 라이선스 | 확인하는 법 | `source` 에 적을 값 |
|---|---|---|---|---|
| 1 | **국가유산포털** (heritage.go.kr) | 공공누리 제1~4유형(항목마다 다름) | 사진 상세의 "공공누리" 배지에서 유형을 확인. **제2유형(상업 금지)은 쓰지 않는다** — 이 앱은 인쇄 주문을 받는다 | `국가유산포털` |
| 2 | **한국관광공사 사진갤러리** (korean.visitkorea.or.kr) | 공공누리 제1유형이 다수 | 내려받기 화면의 유형 표기. 출처 표시 의무가 있다 | `한국관광공사` |
| 3 | **위키미디어 공용** (commons.wikimedia.org) | CC BY / CC BY-SA / Public Domain | 파일 페이지의 라이선스 상자. **CC BY-NC 는 쓰지 않는다**(상업 금지) | `위키미디어 공용` |
| 4 | **사찰 공식 홈페이지** | 개별 허락 | 메일·전화로 받은 허락을 캡처해 남긴다. 허락 없이 쓰지 않는다 | `{사찰명} 공식` |

**쓰지 않는 것** — 블로그·카페·인스타그램·여행 후기 사이트·구글 이미지 검색 결과.
출처가 그 페이지일 뿐 권리자가 아니다.

## 2. 라이선스 판정 규칙

| 표기 | 쓸 수 있나 | 이유 |
|---|---|---|
| 공공누리 **제1유형** | ✅ | 출처 표시만 하면 상업·변형 자유 |
| 공공누리 **제3유형** | ✅ | 출처 표시 + 변형 금지. 자르기·보정을 하지 않으면 된다 |
| 공공누리 **제2·4유형** | ❌ | 상업 이용 금지. 인쇄 주문이 걸린다 |
| **CC0 / Public Domain** | ✅ | 제약 없음. 그래도 `source` 는 적는다 |
| **CC BY / CC BY-SA** | ✅ | 저작자 표시 필수. `credits.json` 의 `source` 에 **사람 이름**까지 적는다 |
| **CC BY-NC / ND** | ❌ | NC 는 상업 금지, ND 는 변형 금지(썸네일 생성이 변형이다) |
| 표기 없음 | ❌ | 없는 것이 아니라 **모르는 것**이다. 폴백으로 둔다 |

## 3. `credits.json` 채우는 법

뼈대는 `frontend/public/sites/credits.json` 에 **110행**이 이미 있다(`siteId` 오름차순).
값은 전부 비어 있고, 아래 넷을 채운다.

```json
{
  "siteId": 990389,
  "name": "통도사 서운암",
  "file": "990389.jpg",
  "source": "국가유산포털",
  "license": "공공누리 제1유형",
  "url": "https://www.heritage.go.kr/..."
}
```

| 칸 | 규칙 |
|---|---|
| `file` | `frontend/public/sites/` 아래 상대 경로. **`{siteId}.jpg` 로 통일**한다 — 이름으로 두면 동명이찰에서 덮어쓴다 |
| `source` | 위 표의 값. CC BY 면 `위키미디어 공용 · {촬영자}` |
| `license` | 위 표의 표기를 **그대로** 적는다. "무료" 같은 말로 바꾸지 않는다 |
| `url` | 라이선스를 확인한 **그 페이지** 주소. 사진 파일 주소가 아니라 라이선스가 적힌 페이지다 |

넷 중 하나라도 비면 그 사찰은 **폴백**으로 나간다. 반쯤 채운 항목이 가장 위험하다 —
파일은 있는데 라이선스가 비어 있으면 "확인했는데 안 적었나" 와 "확인 안 했나" 를 구별할 수 없다.

## 4. 사진 자체의 조건

| 조건 | 값 | 왜 |
|---|---|---|
| 가로세로 | **가로가 긴 사진**(4:3 또는 16:9) | 카드·목록이 가로 썸네일이다 |
| 긴 변 | 1600px 이상 | 상세 화면과 인쇄본이 함께 쓴다 |
| 형식 | JPEG | PNG 는 사진에서 용량만 커진다 |
| 내용 | **사람 얼굴이 알아볼 정도로 크게 나온 사진은 피한다** | 초상권. 전자책이 타인 얼굴 사진을 빼는 것과 같은 이유(챕터 10) |
| 내용 | 절의 **정면·주불전·일주문** 중 하나가 알아보이게 | 목록에서 절을 구분하는 것이 사진의 일이다 |

## 5. 넣기 전 확인

```bash
# credits.json 의 항목 수가 site 표와 맞는가
node -e "console.log(require('./frontend/public/sites/credits.json').items.length)"   # 110

# 라이선스가 빈 항목(= 폴백으로 나갈 사찰)이 몇 개인가
node -e "const c=require('./frontend/public/sites/credits.json'); \
  console.log(c.items.filter(i=>!i.license||!i.file||!i.source||!i.url).length)"
```

## 6. 남은 것

- **봉은사는 이 목록에 없다.** 조사 자료(`sites-master.csv`)에 봉은사 행이 없어서 `siteId 2` 가 빠졌다.
  데모 코스의 다섯 절 중 하나이므로 사진이 필요하다 — 조사 자료에 행을 더하거나 `credits.json` 에 손으로 넣는다.
- 데모 사찰 다섯(조계사 1·봉은사 2·화계사 3·도선사 4·진관사 5)은 시더가 만든 행이 아니라
  `data.sql` 이 만든 행이라 `site-enrich.csv` 에 대응이 없다. 같은 절의 시드 행(990477 등)과
  **중복 등록** 상태라, 어느 쪽에 사진을 붙일지는 그 중복을 정리한 뒤에 정한다(`c1-결과.md` §2).
