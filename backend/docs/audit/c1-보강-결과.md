## 1. mealAvailable 값 체계 변경

### 무엇을 왜 바꾸나

C1(㉓)이 값을 넷으로 접었다 — `NONE` / `TEMPLE_MEAL` / `PUBLIC_MEAL` / `NEARBY`.
그 뒤 확인된 사실이 둘이다.

1. **대부분의 절에 공양이 있다.** "미확인" 은 없다는 뜻이 아니라 조사가 못 미친 것이었다.
2. **다만 시간이 정해져 있고 사전에 연락을 해야 한다.**

②가 값 체계를 바꾼다. 전에는 "있다 / 없다 / 어디서" 만 말했는데, 사용자가 실제로 알아야 하는 것은
**"그냥 가도 되는가, 미리 연락해야 하는가"** 다. 그것을 값이 말하지 않으면 화면은 "공양 가능" 이라고만
띄우게 되고, **시간을 모르고 찾아간 사람이 헛걸음을 한다.**

| 값 | 뜻 |
|---|---|
| `TEMPLE_MEAL` | 사찰음식 특화·체험(명장 등) |
| **`RESERVATION`** | 공양 있음 · 사전 예약/시간 확인 필요 — **기본값** |
| `NONE` | 공양 없음이 **확인된** 곳 — 확인 전에는 쓰지 않는다 |
| `NEARBY` | 경내 공양 없고 인근 식당 — 확인된 곳만 |

`PUBLIC_MEAL`(대중공양)은 뺐다. 조사에서 그 값을 쓴 절이 **한 곳도 없었고**(데모 한 건뿐) 지금 필요한 구분이 아니다.

### 되돌린 것 — 조사 서술로 유추한 TEMPLE_MEAL 49건

앞 회차는 조사 문구에 "사찰음식" 이 있으면 `TEMPLE_MEAL` 로 접었다. 그것을 되돌렸다 —
**조사 문구에 그 말이 있다는 것과 그 절이 사찰음식으로 이름난 곳이라는 것은 다른 말이다.**
대부분의 절은 그냥 공양을 낸다.

`TEMPLE_MEAL` 은 이름을 아는 **여섯 곳**뿐이다 — 진관사 · 봉녕사 · 수도사 · 백양사 · 금수암 · 망경산사.

### 🚨 원문을 한 번 잃을 뻔했다

값을 정규화하면서 `meal_available` 의 원문("사찰음식·서운암 된장 판매" 같은 **68행**)이 덮였다.
`site-enrich-build` 가 `공양원문=` 을 만들 때 그 칸을 읽는데, 그 칸이 이미 `RESERVATION` 이라
**`공양원문=RESERVATION`** 이 되어 원문이 두 번 사라졌다.

백업에서 되살려 **시드 CSV 의 `note` 에 영구 보존**했다(`공양원문=사찰음식·템플스테이` …).
이제 빈 DB 를 다시 세워도 남는다. `site-enrich-build` 는 그 칸을 다시 만들지 않고 있는 것을 실어 나른다.

### `NONE`·`NEARBY` 는 이번에 한 건도 쓰지 않았다

없음이 확인된 절도, 인근 식당만 쓰는 절도 아직 없다. **값 체계에는 남긴다** — 확인되는 대로 들어온다.
`NONE` 을 확인 없이 쓰지 않는 것이 이 체계의 요점이다.

## 2. 프론트 정본에 반영 — `frontend-design-v2.1.md`

값이 넷이 되었으니 **화면이 그것을 무엇이라 부르는지**를 정본이 정해야 한다.
그러지 않으면 프론트가 `RESERVATION` 을 "공양 가능" 으로만 그리고, **시간을 모르고 찾아간 사람이 헛걸음을 한다.**

### §21-1 `MEAL_LABEL` — 값 → 화면 문구

| 값 | 배지 | 함께 보여 줄 한 줄 |
|---|---|---|
| `TEMPLE_MEAL` | 사찰음식 | 사찰음식으로 이름난 곳 · 방문 전 종무소에 문의 |
| `RESERVATION` | 공양 가능 | **방문 전 종무소에 시간·예약 문의** |
| `NONE` | 공양 없음 | 경내 공양이 없다 |
| `NEARBY` | 인근 식당 | 경내 공양은 없고 인근에 식당이 있다 |

**`RESERVATION` 을 "공양 가능" 으로만 띄우면 안 된다** 는 문장을 표 옆에 못 박았다.
값이 곧 안내가 아니라, **값 + 한 줄**이 안내다.

### §14-4 `riderInfo` — 값이 어디로 흘러가나

사찰 상세의 편의 정보 묶음에 `mealAvailable` 이 어떤 필드로 실려 나가는지 적었다.
프론트는 `site.mealAvailable` 을 그대로 받아 `MEAL_LABEL` 로 옮긴다. **서버는 문구를 만들지 않는다** —
문구가 바뀔 때 서버를 다시 배포해야 하는 구조를 만들지 않기 위해서다.

### §14-2·§14-3 동명이찰 표시 규칙

`site.name` 은 `용문사` 하나뿐이고 셋이 있다. 목록·검색·코스 자리 어디서든 **`name(구분)`** 으로 그린다.

```
용문사(남해 호구산)   용문사(예천 소백산)   용문사(양평 용문산)
```

구분 문자열은 서버가 주는 `disambiguation` 을 쓴다. **이름 자체는 건드리지 않는다**(§3).

### 🚨 `all.sh` 가 한 번 무너졌다 — 돌아가는 jar 를 덮었기 때문

첫 실행이 newman 1회차에서 **46 단언 실패**로 멈췄다. 무너진 곳은 전자책 조판이었다.

```
java.lang.IllegalStateException: 한글 폰트를 읽지 못했다: fonts/NotoSansKR-Regular.ttf
Caused by: java.util.zip.ZipException: invalid stored block lengths
```

폰트 파일은 멀쩡했다. **jar 가 앱 밑에서 바뀐 것**이다 — 앱은 04:30 에 떴는데
`./gradlew test` 와 `bootJar` 가 04:58 에 같은 파일을 덮었다. JVM 은 jar 를 연 채로 들고 있어서
**그때까지 안 읽은 자원**을 읽으려는 순간 처음 터진다.

성질이 고약하다.

- 기동은 성공한다. 이미 읽은 클래스는 멀쩡히 돈다.
- **한참 뒤, 그 자원을 처음 쓰는 요청에서만** 터진다.
- 터진 곳(전자책 조판)과 원인(jar 덮어쓰기)이 아무 관련 없어 보인다.

앱을 내리고 다시 구운 뒤 띄워서 재실행했다.

> **규칙에 한 줄 더** — `bootJar` 는 **앱을 내린 뒤에** 돌린다.
> §0 의 "JVM 하나" 에 "굽고 나서 띄운다" 를 붙인다.
